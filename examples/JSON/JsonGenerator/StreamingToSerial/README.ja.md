# StreamingToSerial

> English: [README.md](README.md)

生成するJSONをSerialへ直接出力するサンプルです。

## 準備と実行

1. [サンプル入門ガイド](../../../../docs/GUIDE_EXAMPLES.ja.md)で導入条件と必要な機器を確認します。対応するボード・外部ライブラリはルートREADMEを参照します。
2. [StreamingToSerial.ino](StreamingToSerial.ino)を開き、実際のボードとポートを選びます。次のincludeで使う依存機能も準備してください。

   `<EspHelperJsonGenerator.h>`

3. 書き込んだらシリアルモニタを115200 baudへ合わせます。起動ログとソースの操作条件を確認します。

## 動作の流れ

以下はソース内で最初に現れるAPIの順です。コールバック登録の位置は、実際の呼び出し順序とは異なります。

1. `json.finish(...)` — 生成中の構造を完了し、容量／Errorを確認してから出力を使います。

## APIの使い方と注意点

選んだ例で使うラッパーと外部機器ライブラリだけを導入します。タスク開始前に機器を設定し、最小例を組み込む際はcreate／begin／startの成否を確認します。FreeRTOS用ラッパーの待ち時間はTickType_tで、ESP32SyncKitのms指定とは異なります。

希望時間から変換する場合は `pdMS_TO_TICKS()` を使います。false／0は時間切れ・空き不足・データなしなどを表し得るので、出力を使う前に対象APIを確認します。Queueは要素の値、StreamBufferは区切りのないバイト列、MessageBufferはメッセージ単位で渡します。

RingbufferItemは参照中の領域をRAIIで返却するため、寿命を越えて使うデータはコピーします。ネットワークやイベントのコールバックはloop以外でも動くので、処理を短くし、後で使う値は自分の領域へ保存します。

固定バッファの容量、解析／生成の成功、入力文字列とビューの寿命を確認します。オブジェクト／配列への移動と終了を対応させ、途中の出力を完成したJSON／CBORとして扱わないようにします。

## 確認と問題の切り分け

生成するJSONをシリアルへ直接出力することを出力から確認します。まず例のままの入力で試し、その後に設定やデータ源を1つずつ変えます。

| 症状 | 最初に確認すること |
|---|---|
| 出力がない | ボード／依存ライブラリ、初期化結果、表示先とシリアル速度 |
| 開始するが途中で止まる | 待機条件、バッファの空き、相手や入力の準備、継続呼び出し |
| 値が不自然・不安定 | 長さと単位、形式、寿命、共有状態、部分的な処理結果 |

共通の考え方は[入門ガイド](../../../../docs/GUIDE_EXAMPLES.ja.md)、別の例は[サンプル一覧](../../../README.ja.md)へ進んでください。
